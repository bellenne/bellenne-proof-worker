- Опциональная интеграция с исходниками `BellenneOne/apps/proof`: **1 passed**.
  Этот тест пропущен в обычном наборе, поскольку требует явного `PROOF_CORE_SOURCE`.

- Compose configuration проверена с тестовым существующим source mount.

Интеграционный тест копирует серверное приложение во временный каталог,
использует отдельный Python environment и временную SQLite. Он создаёт synthetic
Job, вызывает Worker по настоящему TCP API, теряет ответ после принятого upload,
перезапускает Worker с сохранённым журналом и убирает source. После восстановления
Job completed, на сервере один Result, локальный и серверный SHA-256 совпадают.
Отключённая CRM delivery имеет отдельный failed-статус и не меняет completed
обработки. Production БД/credentials/исходники Core не изменялись.

Контракт поиска проверен на структуре `заказ / ревизия / Исходник` с числовыми
ревизиями `1/2/3`:
связка `Макет N`, граница номера, единственность папки макета, игнорирование
JPG-preview по умолчанию, неоднозначные TIFF, PSD в новой ревизии,
относительные пути и запрет выхода за source mount.

Runtime smoke test запускал обычный контейнер под непривилегированным пользователем
с заведомо недоступным loopback Core. Контейнер достиг `healthy`, retry backoff
работал, `docker stop` корректно завершил процесс. Тестовый контейнер остановлен.

Через Docker CLI создан и визуально проверен synthetic результат:
`dev-data/demo-output/proof.jpg`, **1701 × 850 px, RGB, 72 DPI**. Исходный TIFF
3600 × 2200 имел 300 DPI; главный crop сохранил масштаб 1:1, а Result получил
72 DPI. Миниатюра 425 × 260 px расположена в (142, 295), рамки соответствуют
выбранным координатам. Диагностика находится в `dev-data/demo-data/`.
Все demo-файлы исключены из Git.

Отдельный native image test обработал одностраничный BigTIFF 20 000 × 12 000 px.
Это проверка большого synthetic изображения, а не benchmark реального NAS.

Ограничения эксплуатации: реальные производственные макеты и SMB отключения
не проверялись в этой среде. Выбор crop нужно оценить на репрезентативных макетах.
Ограничения текущего Core по read-only reconciliation и fencing описаны в
`core-contract.md`; Worker сохраняет спорные результаты для разбора.
