# Сетевая папка через SMB

`docker-compose.smb.yml` — самостоятельная замена `docker-compose.yml` для
рабочей машины с Docker Desktop и Linux-контейнерами.
Он подключает `\\192.168.1.88\дизайн отдел\Макеты (опт)` к `/sources/main`.

Добавьте в существующий `.env` учётные данные файлового сервера:

```dotenv
SMB_USERNAME='имя_пользователя'
SMB_PASSWORD='пароль'
```

У пользователя должны быть права чтения и записи. `SOURCE_MAIN_HOST_PATH`
в этом варианте не используется. Остальные настройки Core и Worker остаются
в существующем `.env`. Файл с паролем не передавайте другим пользователям.

Выполняйте команды из папки проекта. Проверка конфигурации без вывода пароля:

```powershell
docker compose -f docker-compose.smb.yml config --quiet
```

Проверка чтения сетевой папки без запуска обработки заданий:

```powershell
docker compose -f docker-compose.smb.yml run --rm --no-deps --entrypoint ls proof-worker -la /sources/main
```

Если содержимое папки отображается, пересоздайте сервис:

```powershell
docker compose -f docker-compose.smb.yml up -d --force-recreate
```

Не добавляйте основной `docker-compose.yml` через второй `-f`: SMB-файл уже
содержит весь сервис. Если Core находится в общей Docker-сети на этой же машине,
можно дополнительно использовать существующий `docker-compose.bellenne.yml`.

В Core укажите UNC-префикс `\\192.168.1.88\дизайн отдел\Макеты (опт)`
и mount `/sources/main`. Префикс должен совпадать с началом пути из CRM.

Docker сохраняет параметры SMB в созданном volume. При последующей смене
учётных данных одного пересоздания контейнера недостаточно: нужно отдельно
пересоздать именно SMB-volume. Не используйте `down -v`, поскольку он также
удаляет volumes состояния Worker и результатов.
